Emrac

Emrac is a package manager for Arch Linux that works on top of pacman, libalpm, makepkg, and PKGBUILD. For each package it decides whether a local source build is worth it or the binary is the better choice, shows you the plan, and records the change as a transaction you can roll back.

  • Hybrid by design. Build from source when it pays off, install the binary when it does not. You can always override with --source or --binary.
  • One interface. Official repositories, the AUR, and local repositories are searched, inspected, and installed the same way.
  • Plan first. Every change is previewed with sizes, time estimates, conflicts, and the reasons behind each decision.
  • Reversible. Builds run in a sandbox, transactions are logged, and rollback is built in.

Where it stands. The core commands and everything under Available now work today, including the twenty updates that make up release r3. The source-or-binary scoring, build profiles, queue and terminal interface under Planned features are design goals, not shipped.

Available now

  
Release r3 is tagged; the sections marked since r2 arrived with it. Everything below runs today. Each command that changes the system was also tried against a real pacman in a container, and the change list says what was seen for each slice.

  
Everyday commands

  

    
      
search / infoOfficial repositories (libalpm) and the AUR (RPC, with retries) behind one interface. --official, --aur, --offline, --json.

      
install / remove / upgradePreview, confirm, run. upgrade covers official packages and the AUR, holds back pins, and can save a snapshot first. --dry-run changes nothing.

      
build <pkg|dir>Builds an AUR package or a local PKGBUILD folder without installing it, in the sandbox.

      
config / completionPersisted defaults in ~/.config/emrac/config.toml; bash, zsh and fish completion.

    
  

  
Plans that match what pacman does

  

    
      
Fresh previewsThe upgrade plan comes from a throwaway copy of the databases synced just now, so it lists what pacman -Syu will really do. An old package list is called out; an empty plan is never reported as “up to date” from stale data.

      
What will also goPackages removed to resolve conflicts or replacements, and which provider pacman will pick for a dependency, are listed before you confirm, and recorded in the history.

      
pacman’s own questionsWithout --yes pacman asks its own questions. Silence on standard input is never consent: a closed terminal declines.

      
Dependency conflictsWhen an AUR build stops because one package conflicts with another that something still requires, emrac explains which, why, and whether the swap looks safe — and offers it, default no. The plan warns beforehand.

    
  

  
Building AUR packages safely

  

    
      
auditReads a PKGBUILD, its scriptlets and shipped files, and inspects any built package file. Findings are info, warning, high (a default-no prompt that --yes does not answer; --accept-risks does) or critical (refused, no override).

      
Package manifestThe built package is inspected before pacman -U: setuid files, hooks, sudoers, accounts, units, scripts, and which installed packages it would remove.

      
Sandboxbubblewrap: read-only root, empty home, cleared environment, no network unless you allow it. Dependencies and sources are fetched on the host (signatures checked with your keyring); extraction, build and packaging run inside. --no-sandbox exists as a flag only, never a config key.

      
LimitsMemory, process count, temporary size and time are capped (build.* in the config); the kernel’s own counters say which limit stopped a build.

      
Real-world fixesSplit packages are fetched from their base’s repository; fakeroot works inside the sandbox; a failed build offers a retry with the network on only when its output shows a blocked download.

    
  

  
Undo, downgrade and restore

  

    
      
historyAn append-only log of every executed transaction, failures and conflict removals included.

      
rollback / undo / redoReverse and re-apply recorded transactions. Files come from the pacman cache, the AUR build folder, the repositories or the Arch Linux Archive; the current state is checked first.

      
downgrade / reinstall / purgeOne package back to an older version; the same version again; remove a package with its modified configs.

      
snapshot / restoreNamed restore points of the installed package set (not files), optionally saved before every upgrade.

      
pin / unpinHold a package back from upgrade with a reason and an expiry.

    
  

  
Health and housekeeping

  

    
      
doctorRead-only checks with a fix for each finding: dependencies, databases, pending upgrades against fresh repositories, kernel, disk, caches, orphans, .pacnew files, failed units, pins, tools, sandbox. --report writes a sanitized bug report.

      
verify · deps / rdeps / why / orphansInstalled files against pacman’s record; read-only dependency inspection.

      
pacnewFinds .pacnew and .pacsave files and compares the file the old package shipped, your live file and the new one, so your edits are told from upstream’s. Keep, take, merge or edit each; the result is checked first (sudoers, sshd_config, pacman.conf, fstab, mirrorlist, JSON, shell files), both files are saved, every change is recorded and pacnew revert puts it back.

      
cacheSource, build, binary and pacman caches: list, stats, clean, trim, purge (cc and cs shortcuts). clean keeps what undo needs; --lean keeps one rollback set and drops the rest.

    
  


  
Before a change, and after since r2

  

    
      
Pre-flight checksBefore anything is asked or changed: free space on /, for the downloads, on /boot and the EFI partition; the battery; that a mirror answers; and for a kernel upgrade, that another kernel is installed, the fallback initramfs exists and the bootloader names the image. Removing the last kernel is refused. /boot is often readable by root only; those checks then say so instead of guessing.

      
Partial-upgrade gateInstalling or upgrading only some packages while others have upgrades waiting is refused, with the packages named and emrac upgrade as the fix; --allow-partial lets one run through. A plan that would install an older version than the one you have is refused too.

      
Plan idsEvery plan shows an id (digest in --json). --expect-plan runs only that plan, and a plan you looked at for half a minute or more is made again just before it commits and must be the same. The id is kept in your history.

      
Update risk, and the reportAn upgrade plan says LOW, MEDIUM or HIGH and why (a new kernel, glibc, systemd, pacman, the bootloader, critical news…). Afterwards, and with emrac report: whether to reboot, services still running old files, new failed units, AUR packages the upgrade broke, new .pacnew files.

      
pacman’s own databaseA small backup of the local package database before each transaction, pacman -Dk before and after, the restore command if it came out worse, and a warning when a repository serves data older than you have seen.

    
  

  
Trust since r2

  

    
      
AUR trust signalsIn the review and in info: a name one letter from a real package, orphaned or very new packages, a changed maintainer, sources or checksums that changed under the same version, a new source host, changed signing keys. The serious ones ask a default-no question.

      
newsThe Arch Linux news, with what you have not seen marked, shown under every upgrade plan. A breaking change, a request for manual intervention, or news touching the kernel, bootloader, glibc, systemd, pacman or drivers stops the upgrade until you have read it (news ack, or --ack-news once); the rest only warns.

    
  

  
History you can check, and emrac itself since r2

  

    
      
history · ledgerEvery record is chained to the one before by a hash, so history verify finds an edit; old records can be archived and failures acknowledged. A second, root-owned append-only copy (the ledger) is kept through sudo; history verify compares them and can rebuild the history from it, and optional kernel audit rules report what else touched it. A short history anchor code kept elsewhere shows a rewrite or a cut-off tail. It does not stop root, and says so.

      
Cut-off transactionsA journal written before pacman runs and locked while it does: after a power cut or a killed terminal the next run, or history recover, reads pacman’s log, says which packages were done and which were not reached, and records it.

      
rebuildBuilds installed AUR packages again from source through the same audit, after a library, Python or Qt update broke them; --check says which ones, and why. Binary (-bin) packages are named and left alone, since rebuilding them fixes nothing.

      
tree · graph · impact · cyclesA package’s dependencies as a tree or Graphviz source; what removing, installing or upgrading it would affect, with services and desktop entries; packages that require each other.

      
selfcheck and diagnose look at emrac’s own installation; sync and news keep a checked copy of the release index; upgrade and downgrade download a release, verify it, build a package and install it with pacman. Only a copy a pacman package owns is ever changed.

      
configThe settings file is framed and documented (what each key does, its default, what changed); config refresh brings an older file up to that form.

    
  



  
Planned features

  
The design goals. Those not listed under Available now are not built yet.

  

    
      
Search and inspectFast local index, fuzzy and regex search, file ownership lookup, and changelogs in info.

      
Build profilesReusable profiles for compiler, linker, optimization level, LTO, PGO, and CPU tuning. Profiles can inherit from other profiles.

      
Build queueQueue, pause, and resume builds, with live progress and an ETA that refines as the build runs.

      
News and advisoriesThe Arch news gate is built (see Trust above). Still to come: ABI-transition notices and security advisories for the packages you actually have installed.

      
Health checksemrac doctor checks for broken and orphaned packages, partial upgrades, mirror health, and configuration problems.

      
History and rollbackA transaction ledger with snapshots, rollback to a point in time, and per-package restore.

      
Terminal interfaceA full TUI with a package browser, dependency explorer, build monitor, news reader, and a built-in modal editor for PKGBUILDs. The CLI exposes the same functions.

Safety

  
Every change is a transaction

  

    

      Planned→
      Previewed→
      Confirmed→
      Executing→
      Committed
    

    
Declined or --dry-run: nothing is changed. Failed: roll back with emrac undo (resuming an interrupted step is planned).

  


  
Four layers between a request and your system

  

    

      
Planin memory
A virtual transaction tree is computed first: files, sizes, disk impact, and services. Nothing is written.

      
Sandbox buildisolated
Sources are built in an isolated overlay. A failed build leaves no artifacts on the host.

      
SnapshotBtrfs or ZFS
Planned: where supported, a filesystem snapshot before commit as a fallback for power loss or a failed write. Today emrac snapshot saves the installed package set, not files.

      
Commitpacman
The verified package is installed by pacman itself, so pacman's own conflict and safety logic stays in charge.

Theming

  
The TUI and the colored CLI output read the same theme tokens: background, panel, border, text, and one accent. Pick a built-in theme, or inherit from one and override what you need. This page uses the same tokens, so the Theme menu in the navigation bar changes it live.

Backgrounds are separate from themes: peaks, grid, schematic, scan, or none. Choose one from the Theme menu. There are a few more that are not listed.

Download

  
Emrac is at release r3. The install script builds a pacman package from the release tarball (after checking its checksum) and installs it with pacman, so pacman -Rns emrac removes it. The AUR and a binary repository are not published yet, so those tabs show the intended commands. Read a script before you run it.
