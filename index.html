Emrac

Emrac is a package manager for Arch Linux that works on top of pacman, libalpm, makepkg, and PKGBUILD. For each package it decides whether a local source build is worth it or the binary is the better choice, shows you the plan, and records the change as a transaction you can roll back.

  • Hybrid by design. Build from source when it pays off, install the binary when it does not. You can always override with --source or --binary.
  • One interface. Official repositories, the AUR, and local repositories are searched, inspected, and installed the same way.
  • Plan first. Every change is previewed with sizes, time estimates, conflicts, and the reasons behind each decision.
  • Reversible. Builds run in a sandbox, transactions are logged, and rollback is built in.

Features

  

    
      
Search and inspectFast local index, fuzzy and regex search, file ownership lookup, dependency and reverse-dependency trees, and emrac why to explain why a package is installed.

      
Build profilesReusable profiles for compiler, linker, optimization level, LTO, PGO, and CPU tuning. Profiles can inherit from other profiles.

      
Build queueQueue, pause, and resume builds, with live progress and an ETA that refines as the build runs.

      
News and advisoriesManual intervention notices, ABI transitions, and security advisories for the packages you actually have installed.

      
Health checksemrac doctor checks for broken and orphaned packages, partial upgrades, mirror health, and configuration problems.

      
History and rollbackA transaction ledger with snapshots, rollback to a point in time, and per-package restore.

      
Terminal interfaceA full TUI with a package browser, dependency explorer, build monitor, news reader, and a built-in modal editor for PKGBUILDs. The CLI exposes the same functions.

Safety

  
Every change is a transaction

  

    

      Planned→
      Previewed→
      Confirmed→
      Executing→
      Committed
    

    
Declined or --dry-run: nothing is changed. Failed: resume the step with emrac queue resume, or roll back.

  


  
Four layers between a request and your system

  

    

      
Planin memory
A virtual transaction tree is computed first: files, sizes, disk impact, and services. Nothing is written.

      
Sandbox buildisolated
Sources are built in an isolated overlay. A failed build leaves no artifacts on the host.

      
SnapshotBtrfs or ZFS
Where supported, a filesystem snapshot is taken before commit as a fallback for power loss or a failed write.

      
Commitpacman
The verified package is installed by pacman itself, so pacman's own conflict and safety logic stays in charge.

For AUR maintainers

  
Emrac also helps with publishing. It runs the pre-submission checks in a clean sandbox before anything is pushed. Credentials stay with you: you configure your own SSH key, and only the push step can read it.

Theming

  
The TUI and the colored CLI output read the same theme tokens: background, panel, border, text, and one accent. Pick a built-in theme, or inherit from one and override what you need. This page uses the same tokens, so the Theme menu in the navigation bar changes it live.

  

  

    
~/.config/emrac/config.tomlupdates as you choose

    

  

  
Backgrounds are separate from themes: peaks, grid, schematic, scan, or none. Choose one from the Theme menu. There are a few more that are not listed.
