# feats/

The collected feature ideas for emrac. Nothing here is a commitment unless it says it is built or specified; what has been built is tracked in the root [`FEATURE_STATUS.rst`](../../FEATURE_STATUS.rst) and, for everything at once, in [`feats.md`](./feats.md).

- [`feats.md`](./feats.md) — **every feature in one file**: built, partly built, specified, proposed, research, and decided against, with the status of each and where it is documented. Start here.
- [`SPEC.md`](./SPEC.md) — the product specification.
- [`additions.md`](./additions.md) — ideas A1-A22, B1-B9 and the critical features C1-C8.
- [`ideas.md`](./ideas.md) — ideas gathered from other projects and from use: security and trust, safety and recovery, workflow, intelligence, Arch-specific safety, install-time transparency, the maintainer workflow for publishing to the AUR, and emrac's own tooling. Items are marked `[idea]` or `[built uN]`.
- [`cross-distro-feat.md`](./cross-distro-feat.md) — "Wandrover", the design for cross-distribution package discovery and resolution: finding the Arch package that provides the same software as a package from another distribution. Not built.
- [`self-service-feat.md`](./self-service-feat.md) — the self-management service, `emrac self`. Built.
- [`aur-defense-feat.md`](./aur-defense-feat.md) — layered AUR malware defense. Planned for the r4 cycle.
- [`rea-research-plan.md`](./rea-research-plan.md) and [`rea-portage.md`](./rea-portage.md) — the research programme and what to learn from Portage.
- [`pkgforensics.md`](./pkgforensics.md) — package forensics: timeline, provenance, persistence, baseline, evidence capture. Proposed.
- [`plugin-feat.md`](./plugin-feat.md) — the plugin system: WebAssembly modules (never scripts) with enforcement and security checks; extension points, capabilities, install checks, phases, open choices. Proposed.
