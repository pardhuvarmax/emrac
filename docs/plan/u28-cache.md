# Slice u28 — `emrac cache`: see, clean, trim and purge what emrac and pacman keep

`SPEC.md` (§13, and the `cache` reference) names four caches and the commands
`list / stats / verify / clean / purge / trim / export / import`. On the first real
upgrade `~/.cache/emrac/build` was 14 GB and pacman's cache 7.3 GB, with nothing to
look at or trim them.

## What each category is, on disk

| Category | Scope word / letter | What | Where |
|---|---|---|---|
| source | `source` / `s` | downloaded source files (tarballs, zips, `.deb`s) | top level of each `~/.cache/emrac/build/<pkg>/`, untracked by git, not a package file |
| build | `build` / `b` | extraction and staging trees | each build folder's `src/` and `pkg/` |
| binary | `binary` / `n` | built package files, and packages fetched from the Arch Linux Archive | `*.pkg.tar.*` in the build folders; `~/.cache/emrac/archive/` |
| package | `package` / `p` | pacman's package cache | `/var/cache/pacman/pkg` (root-owned; deleted through `sudo`) |

The AUR checkouts themselves (`.git`, `PKGBUILD`, `.SRCINFO`) are never cache: deleting
them would forget which PKGBUILD was reviewed. No category touches them.

## Commands

- `emrac cache [list]` — per category: files, size, oldest and newest; `list` adds the
  largest packages. `--json`.
- `emrac cache stats` — the totals, and how much `clean` would free.
- `emrac cache clean [SCOPE]` — remove what is safe to lose (below). Without a scope:
  build, binary and package. `source` only when named, because some sources cannot be
  downloaded again by a program (a vendor that wants a login).
- `emrac cache trim --size-limit <size> [SCOPE]` — remove the oldest of what `clean`
  would remove until the scope is under the limit; if it still isn't, say so rather
  than touching protected files.
- `emrac cache purge [SCOPE]` — remove everything in the scope. Without a scope it
  needs `--force`.
- Always: `--older-than <duration>` (`30d`, `12h`, `2w`), `--dry-run`/`-n`, `--force`/`-f`,
  `--yes`/`-y`, `--json`. A scope may also be given as `--source` etc.
- Short forms (fixed aliases only, no prefix matching): subcommands `l s c p t`, top-level
  `cc` and `cs`, `-o` `-m` `-n` `-f`.

Not built: `verify`, `export`, `import`, the interactive cache manager (`-i`), and
`emrac cleanup --cache`. They are not listed in `--help`, so nothing pretends to work.

## What is safe to lose

- **build**: all of `src/` and `pkg/` — regenerated by the next build.
- **binary** and **package**: a package file is kept if it is the installed version or
  the newest older one (so `downgrade` and `undo` keep working), or if any of the last
  20 recorded transactions mentions that exact version (so `undo`/`redo` of them
  works). Everything else older than `--older-than` (default: any age) goes. Files for
  packages that are no longer installed go too, unless a recent transaction mentions
  them.
- **source**: files older than `--older-than` (default 30 days).
- `purge` ignores these protections but says what that costs: no `undo` of those
  versions, sources to download again, a full rebuild.

## Safety

- `--dry-run` lists every path's category, size and the reason it is eligible or kept.
- Without `--yes` a summary (counts and bytes per category) is shown and confirmed,
  default no; closed stdin is no.
- Paths are checked to lie under the four roots; symlinks are removed, never followed;
  read-only directories (Go module caches) are made writable before removal.
- The package cache is not touched while `/var/lib/pacman/db.lck` exists. Deleting it
  runs `sudo rm` in batches; the summary says so up front.
- Detached `.sig` files go with their package.

## Not covered

Per-package selective deletion by name; automatic cleanup after upgrades (a config key
is the natural next step); sources in a custom `SRCDEST`; cache of the Arch news or the
AUR RPC (none exists).

## Verification

Unit tests: duration and size parsing, scope words and letters, which package files are
protected, the trim order. Container: a fake build folder with `src/` and `pkg/` trees
containing a read-only directory, a symlink out of the tree, sources and built packages;
a pacman cache with three versions of a package (one installed) — `clean --dry-run`
changes nothing; `clean` leaves the installed and the previous version; `trim` stops at
the limit; `purge --build` without `--force`, with piped answers and with closed stdin.
