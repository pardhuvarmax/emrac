# emrac r3-u1

Tag `r3-u1`, 2026-10-16. Version `0.3.1`. Built by pardhuvarmax — https://github.com/pardhuvarmax/emrac

Emrac updates a copy no package owns in place (self upgrade and downgrade), the tests ignore makepkg's folder variables, and releases are published by a pipeline with a review and an approval step

Channel: stable

## What is new

- **`emrac self upgrade` and `self downgrade` work on a copy no package owns** (installed with `cargo install`, or put in `~/.local/bin` by hand) when you can write to its folder: the release is checked against the index, built with cargo, run from staging and from its folder, the old file is kept in `~/.local/share/emrac/self/previous/`, the new one is renamed over it in one step, and the old one is put back if the new one does not report the version. The packaged copy is still updated through pacman. Nothing asks for root.
- The command-line tests no longer break when makepkg's folder variables are set (they leaked in from `self upgrade`), and `self upgrade` removes its staging folder even when a build left folders nobody can enter.
- `self check` points at `self upgrade` instead of saying emrac cannot update itself.
- Releases are published by a pipeline: a tag push runs checks, a review report, an approval step, then publishes (`dev/release.sh`, `docs/design/releasing.md`).

## Updating

`emrac self sync` and then `emrac self upgrade` (or your AUR helper, or pacman with the new package).
Requirements and known limits are those of r3; an in-place update needs only `cargo`, a C compiler and `tar`.
