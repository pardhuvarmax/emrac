# emrac r2

Released 2026-10-14. Built by pardhuvarmax — https://github.com/pardhuvarmax/emrac

emrac is a hybrid package management platform for Arch Linux: an orchestration layer over `pacman`, `makepkg`, `libalpm` and the AUR. Release r1 shipped the core loop. r2 is that loop made safe to use on a real machine: you can read what an upgrade will do before you confirm it, AUR packages are reviewed, audited, built in a sandbox and inspected before they are installed, every change can be reversed, and the config files an upgrade leaves behind can be sorted out without guessing.

## What is new since r1

r2 contains everything from the update slices u15 to u30 (u1 to u14 were already in r1).

### Upgrades you can read before you press y
- **The preview is built from repositories synced just now**, so it lists what `pacman -Syu` will really do. An old package list is called out; an empty plan is never reported as "up to date" from stale data. (u22)
- **What will also go.** Packages removed to resolve conflicts or replacements, and the provider pacman will pick for a dependency, appear in the plan and in `--json`, and are recorded in the history. (u24, u25)
- **pacman's own questions pass through** unless you give `--yes`. Silence on standard input is never consent: a closed terminal declines. (u23)
- **Dependency conflicts are explained.** When an AUR build stops because one package conflicts with another that something still requires, emrac says which, why, and whether the swap looks safe, and offers it (default no, `--yes` does not answer). The plan warns beforehand. (u26)

### AUR builds you can trust a little more
- **Review and audit.** Each package shows its PKGBUILD (or the diff since you last reviewed it) and is audited: static reading of the PKGBUILD, scriptlets and shipped files. Findings are info, warning, **high** (a default-no prompt that `--yes` does not answer; `--accept-risks` does) or **critical** (refused, no override). (u15–u18)
- **Sandbox.** Dependencies and sources are fetched on the host (signatures checked with your keyring); extraction, build and packaging run in bubblewrap with a read-only root, an empty home, a cleared environment and no network unless you allow it. `--no-sandbox` exists as a command-line flag only, never a config key. (u19)
- **Limits.** Memory, process count, temporary size and time are capped (`build.*` in the config), and the kernel's own counters say which limit stopped a build. (u20)
- **The built package is inspected** before `pacman -U`: setuid files, hooks, sudoers entries, accounts, units, scripts, and which installed packages it would remove. `emrac audit <file.pkg.tar.*>` does this for any package file. (u17)
- **`emrac build`** builds an AUR package or a local PKGBUILD folder without installing it.

### Undo
`history`, `rollback` / `undo` / `redo`, `downgrade`, `reinstall`, `purge`, `snapshot` / `restore` and `pin` / `unpin` (r1) now work after a real upgrade: files come from the pacman cache, the AUR build folder, the repositories or the Arch Linux Archive, and the system is checked first. Failed transactions are recorded with what they really changed.

### Health
`emrac doctor` is a set of read-only checks, each with a fix: dependencies, databases, pending upgrades against freshly synced repositories, the running kernel and its modules, disk, caches, orphans, `.pacnew` files, failed units, pins, tools and the sandbox. `--report` writes a sanitized bug report. (u21)

### Config files an upgrade leaves behind
`emrac pacnew` finds `.pacnew` and `.pacsave` files and compares three texts — the file the old package shipped, your live file and the new one — to tell your edits from upstream's. It merges what is safe, lets you edit a conflicted merge by hand, and checks the result before applying it (sudoers, sshd_config, pacman.conf, fstab, the mirrorlist, JSON, shell-sourced files). Both files are saved, every change is recorded, and `pacnew revert` puts a file back unless it was edited since. (u27, u30)

### Caches
`emrac cache` shows the source, build, binary and pacman caches; `clean`, `trim` and `purge` change them. `clean` keeps what `undo` needs; `--lean` (or `cache.policy = "lean"`) keeps one rollback set — what undoing the last `cache.keep_days` days needs, AUR builds and held-back packages — and drops the rest. (u28, u29)

### Found by the first real upgrade
r2 was shaped by running emrac on a real machine: a full upgrade of 388 packages (365 official, 23 AUR). It found and fixed:
- a split package (`stm32cubemx-jre`) cloned from an empty repository;
- fakeroot failing inside the sandbox on `cp -a` and `chown`;
- signatures re-checked inside the sandbox with an empty keyring;
- a network-retry prompt offered after failures that had nothing to do with the network;
- a dependency-step failure reported only as "exit status 8" (now explained, see above);
- false `download-then-run` findings caused by `>/dev/null`;
- a dry run that printed every kept file;
- `redo` unable to fetch a current version from the mirrors after a lean clean;
- a time-window rule for the lean cache, because one upgrade session left ten history records.

## Before you update from r1

- **`emrac --version`** now prints three lines (version, "built by", project URL).
- **AUR builds need bubblewrap** (or `--no-sandbox`, which runs the build with your full access) and have no network unless you allow it (`--allow-network`, or answer the prompt).
- **Without `--yes`, pacman asks its own questions** during `install` and `upgrade`.
- **`-n`** is now also the short form of `--dry-run`.
- **`--json`** plans gained `removals`, `provider_choices` and `warnings`; history records gained `removed`. Existing history and config files keep working; the new config sections (`[build]`, `[cache]`) are optional.
- **New files:** `~/.local/share/emrac/pacnew-log.jsonl` and `config-backups/` (`pacnew`), `~/.cache/emrac/archive/` (packages fetched from the Archive).

## Requirements

`pacman` with `libalpm`, `makepkg`, `git`, `sudo`, `bsdtar` (libarchive) and `fakeroot`. `bubblewrap` for sandboxed AUR builds; a systemd user session for memory and process limits (without one emrac warns and applies the time and size limits only). Network access for the AUR, the Arch Linux Archive and `pacnew --fetch`.

To build: a recent Rust toolchain, `libalpm` headers and `clang`. `dev/release-build.sh` makes a release build that embeds none of the builder's paths.

## How it was checked

- 271 automated tests (244 in the core library, 18 CLI integration, 9 CLI unit), run with clippy `-D warnings` and `cargo fmt --check`.
- 26 end-to-end checks with this release's binary against a real pacman in a podman container: search and info, install and remove, history, verify, snapshots and restore, pin, undo and redo, audit, an AUR build in the sandbox from install to `pacman -U`, `cache`, `pacnew`, `doctor`, `config`, completion, exit codes, and "a closed stdin declines".
- Every slice from u15 to u30 was also exercised in a container against a real pacman before it was committed; `CHANGELOG.md` says what was seen for each.
- The first real full upgrade described above.

## Known limits

- **Not built:** the terminal interface, build profiles and optimization, the build queue, the source-or-binary recommendation, an Arch news check before upgrades, `locate`, `lock` / `unlock`, filesystem snapshots (`snapshot` saves the package set only), a Landlock layer, dependency graph and impact views, and the cross-distro "Wandrover" idea.
- **Audit is static.** Compiled binaries inside a package are only counted; findings are per file apart from one cross-file exfiltration rule.
- **Plans** assume the default for every provider question, and a provider choice that appears only at `pacman -U` of a built AUR package is not shown in advance. The plan warning for AUR dependency conflicts uses the AUR's `Depends` (not `MakeDepends`) and only packages already cloned or listed.
- **`pacnew`** looks at most six upgrades back for the old file, makes no two-way merge (without the old file nothing separates your edit from upstream's) and does not flag an unknown option in `pacman.conf` (pacman ignores it too).
- **`cache`** has no `verify`, `export`, `import` or interactive manager.
- **The sandbox** needs unprivileged user namespaces, and the build's output goes through a pipe, so tools inside it show no colours or progress bars.
- **Rollback** is package-level only. There are no filesystem snapshots, so changes to files outside packages are not undone (apart from `pacnew revert`).

## Versioning

emrac numbers its work in slices, not semver: `i` for incubation, `r` for releases, `u` for updates within a release. r2 closes the updates counted against r1 (u1–u30); the next update is u1 against r2. The crate version in `Cargo.toml` follows the release (`0.2.0`).
