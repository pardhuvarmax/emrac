# emrac r1

Released 2026-10-13. Version `0.1.0`. Built by pardhuvarmax — https://github.com/pardhuvarmax/emrac

emrac is a hybrid package management platform for Arch Linux: an orchestration layer over `pacman`, `makepkg`, `libalpm` and the AUR. r1 is the first release: the core loop works end to end, and the update slices u1 to u14 were built on top of it before the cut.

## What r1 does

- **The core loop.** `search`, `info`, `install`, `remove` and `upgrade` over the official repositories (libalpm for reads, `pacman` for changes) and the AUR (RPC, `git`, `makepkg`). Each shows a transaction preview and asks before it changes anything; each has `--dry-run` and `--json`. An AUR package's PKGBUILD is shown for review before it is built.
- **Undo.** `history` records every transaction; `rollback` / `undo` / `redo` reverse and replay them; packages come from the pacman cache or the Arch Linux Archive (u3–u5). `downgrade` (u6), `reinstall` (u7), `purge` (u8).
- **Check and protect.** `verify` compares a package's files with pacman's record (u9). `pin` / `unpin` hold packages back from `upgrade`, with a reason and an optional expiry (u13).
- **Snapshots.** `snapshot` and `restore` save and return to the installed set; `snapshot.before_upgrade` takes one before every upgrade (u10, u11).
- **Dependencies.** `deps`, `rdeps`, `why` and `orphans` (u12), read-only.
- **Setup.** A config file (`emrac config`, u1) and bash, zsh and fish completion (u2).
- **Hardening.** Quiet exit on a closed pipe (`emrac … | head`), documented exit codes (`0` success, `1` an error, `2` a usage error), the first command-line integration tests and the CI workflow (u14).

## How it was checked

111 tests (102 in the library, 8 command-line, 1 more in the binary), format and lints clean. In a podman container against a real pacman: search, info, install and remove, snapshot and restore, history with rollback, undo and redo, verify, deps, why and orphans, downgrade from the Archive, pin with a held-back upgrade, reinstall, purge, and the exit codes.

## Known limits

No TUI, no build profiles, no sandboxed builds, no `lock`, no `tree` / `graph` / `impact`. AUR support is what `makepkg -si` does, plus the PKGBUILD review. These arrived in r2 and r3.

## Updating

r1 is superseded: r2 and r3 contain everything here. See [`r2.md`](./r2.md) and [`r3.md`](./r3.md), and `emrac self upgrade` on r3 or later.
