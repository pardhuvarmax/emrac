# Emrac Third Release : R3

Tag `r3`, 2026-10-15. Version `0.3.0`. Built by pardhuvarmax — https://github.com/pardhuvarmax/emrac

emrac is a hybrid package management platform for Arch Linux: an orchestration layer over `pacman`, `makepkg`, `libalpm` and the AUR. r1 shipped the core loop and r2 made it safe to use on a real machine. r3 is about **trust**: you can check what emrac recorded, what you approved is what runs, a transaction that is cut off is not lost, the AUR and the Arch news are looked at before they can hurt, and emrac can update itself through pacman. It contains everything from the twenty update slices `u1` to `u20` built after r2 (the slice numbers started again at `u1` after r2).

## What is new since r2

### A history you can check
- **Hash-chained history.** Every record is chained by SHA-256 to the one before, so `emrac history verify` names the first line that was edited, removed or added. `history archive --older-than` moves old records into archive files (it never touches the newest 20 and always asks); `history ack` marks failures as seen. (u7)
- **A second copy you cannot edit.** After each change the new lines are appended to `/var/lib/emrac/ledger.jsonl`, a root-owned append-only file, through `sudo emrac ledger-append`, a helper that checks every line. `history verify` compares the two copies, `history verify --repair` rebuilds the history from the ledger, and `history sync` catches the ledger up. (u8)
- **The ledger watches itself.** `sudo emrac ledger watch install` adds kernel audit rules; `emrac ledger events` lists what else touched the ledger (the program, the user, the login user, and for `chattr` the command run); `history anchor` prints a short code to keep elsewhere, and `history verify --against CODE` shows a rewrite or a cut-off tail. This does not stop root, and the documents say so. (u9, and `ledger events --ack`)
- **A cut-off transaction is not lost.** A journal is written before pacman runs and locked while it does. After a power cut or a killed terminal the next run, or `history recover`, reads pacman's log and the installed versions, says which packages were done, not reached or changed otherwise, and records it. (u10)

### What you approved is what runs
- **Pre-flight checks** before anything changes: free space on `/`, for downloads, on `/boot` and the EFI partition; the battery; that a mirror answers; and for a kernel upgrade, another kernel installed, the fallback initramfs, the boot entry; removing the last kernel is refused. (u17)
- **A gate against partial upgrades**: installing or upgrading only some packages while others have upgrades waiting is refused, with the packages named (`--allow-partial` for one run). A plan that would install an older version than the installed one is refused too. (u17, u20)
- **Plan ids.** Every plan shows an id (`digest` in `--json`); `--expect-plan` runs only that plan; a plan you looked at for 30 seconds or more is made again just before it commits and must be the same. The id is in every history record. (u18)
- **Update risk and the report.** Each upgrade plan says LOW, MEDIUM or HIGH and why. After an upgrade, and with `emrac report`: a reboot when the running kernel is older than the installed one or glibc, systemd or the firmware changed, services started before an upgraded package, new failed units, broken AUR packages, new `.pacnew` files. (u20)
- **pacman's own database** is backed up before each transaction (the newest 3), checked with `pacman -Dk` before and after, and the restore command is printed if a transaction left it worse. (u20)

### Trust
- **AUR trust signals** in the review and in `info`: a lookalike name, a claim on an official package, orphaned or new packages, a changed maintainer, sources or checksums changed under the same version, a new source host, changed signing keys. The serious ones ask the default-no question. (u20)
- **The Arch news.** `emrac news` lists the news and what you have not seen; unread news is shown under every upgrade plan. It only warns, **except** news that is risky: a breaking change, a request for manual intervention, or a title touching the kernel, the bootloader, the C library, systemd, pacman, drivers or the filesystem layout stops the upgrade until you have read it and run `emrac news ack` (or pass `--ack-news`). (u20)
- **Repository data older than one you have seen** is a warning. (u20)
- **emrac's voice.** Twelve verbs (`found`, `says`, `warns`, `suspects`, `suggests`, `confirms`, …) say how sure a line is and what to do with it. (u6)

### Rebuild what an update broke
- **`emrac rebuild <pkg>`** builds installed AUR packages again from source through the same audit and review, with every makepkg phase forced. **`--check`** lists the AUR packages that are broken now (a program or library needs a shared library nothing provides; files in an old Python or Perl folder) and those that may break (a bundled plugin with a missing library; a package built before Qt's minor version changed), **`--stale`** rebuilds the broken ones. Binary (`-bin`) packages are named and left alone: rebuilding them fixes nothing. (u19)

### emrac updates itself, through pacman
- **`emrac self check` / `diagnose`** look at emrac's own installation (the binary, how it was installed, the configuration, the history, the journals, the ledger helper, what an upgrade needs); they need no pacman, network or root.
- **`self sync` / `self news`** keep a validated copy of the project's release index (`releases.json` on the project page; an optional detached gpg signature checked against a key you set) and show its news.
- **`self upgrade` / `self downgrade`** download a release, check its SHA-256 against the index, build a package with `makepkg` from the same recipe as `install.sh` and the AUR package, and install it with `sudo pacman -U`. Only a copy a pacman package owns is ever changed; a backup is taken first; a refused downgrade explains why. (u11–u15)

### Dependency views
`emrac tree`, `graph` (text, Graphviz `dot`, JSON), `impact` (what removing, installing or upgrading a package affects, including services and desktop entries) and `cycles`. (u16)

### Smaller things
A framed, documented `config.toml` (what each key does, its default, what you changed) with `emrac config refresh`; a warning when emrac runs as root; the credit and `Sic Mundus Creatus Est.` in `--version` and every `--help`; a GPL-3.0-or-later license; `install.sh` that checks a pinned checksum and installs a pacman package. (u1–u5)

## Before you update from r2

- **Stricter by default.** A transaction can now be stopped by a pre-flight problem (not enough space, a missing way to boot, a running pacman), by the partial-upgrade gate, by an older-version gate, and an upgrade by critical unread Arch news. `safety.preflight`, `safety.partial_upgrade` and `safety.arch_news` (`warn` or `off`) relax each; `--allow-partial` and `--ack-news` pass one run. After your first `emrac news ack` or upgrade, "unread" means news since then.
- **The ledger needs `sudo`.** It is written through `sudo -n` right after pacman, while sudo's credential is still fresh, so it never prompts on its own. When that does not work (no sudo, an expired credential) emrac carries on and `emrac history sync`, which asks for your password, catches the ledger up. The history file gained `seq`/`prev` chain fields on the first new record; older lines are kept and counted as "before the chain".
- **New files**, all under your home except the ledger: `journal.json`, `aur-trust.json`, `news.json`, `repo-marks.json`, `pacman-db/` and `self/` in `~/.local/share/emrac/`; the ledger in `/var/lib/emrac/`; optionally `/etc/audit/rules.d/50-emrac-ledger.rules`.
- **Your `config.toml`** is rewritten in the documented form the first time emrac writes it (`emrac config refresh` does it at once); your values are kept, your comments are not.
- **`emrac --version`** prints four lines now.
- Running emrac as root prints a warning (except for `ledger` and `completion`); you do not need it.

## Requirements

- **Run time:** `pacman`, `git`, `sudo`, `libarchive`, `fakeroot`, `tar` (for the database backup) and `bubblewrap` (for AUR builds in the sandbox). Optional: `gpg` (a signed release index), the `audit` package with `auditd` (the ledger watch), `systemd` (limits for builds; unit checks in the report).
- **Build time:** a Rust toolchain, `clang`, and the libalpm headers that come with `pacman`.
- **`self upgrade`** needs `makepkg`, `cargo`, a C compiler and about 2 GiB free where the build runs; `emrac self diagnose` checks all of it.

## How it was checked

- 440 automated tests (401 in the library, 11 unit and 28 integration tests for the command line), clippy with `-D warnings` and `cargo fmt --check` on every change; the list is `docs/tests/emrac-tests.rst`.
- Three container suites against a real pacman (`dev/e2e/run.sh`): 50 checks of the commands; `preflight` (24 checks, with a local repository so that an upgrade is really waiting, a fake kernel, a critical news feed, a corrupted database); and `self` (11 checks: a 0.8.0 package is built and installed, a tampered tarball is refused, an upgrade is killed halfway and found, and a real `self upgrade` to 0.9.0 and `self downgrade` back end with the pacman database showing the version).
- On the developer's machine: a real ledger with real `chattr` and `sed` events, a ledger restored by hand after a test append corrupted its chain (an append-only file still allows appends; emrac caught it and refused to extend it), the audit log read through `log_group`, `emrac report` finding a service still running from before an upgrade, `rebuild --check` finding `quickshell-git` after the Qt 6.12 update, and the Arch news classified from the live feed.
- Mistakes the tests and the runs found on the way, and fixed: a lookalike rule that flagged `quickshell-git` for providing `quickshell`; news items called critical because their body said `pacman`; the whole feed counting as unread; a re-check of the plan that used a database it had already read; a report that said the running kernel "has been removed" inside a container.

## Known limits

- The same list as r2 for what is not built: no terminal interface, no build profiles or queue, no source-or-binary recommendation (`source`, `binary`, `recommend`, `explain`), no security advisories or CVE data, no `locate`, `lock` or `unlock`, no filesystem snapshots, no Landlock layer, no rescue binary, no privilege separation.
- The ledger and its watch make tampering visible; they do not stop root. A signed index is optional and no signing key is published yet.
- `self upgrade` needs a release in the index with a higher version; r3 is the first that has `0.3.0` in it.
- pacman still resolves the versions at install time: the plan is checked up to the commit, not in the seconds after.
- Kernel checks that read `/boot` degrade to notes where `/boot` is readable by root only. Secure Boot and unified-kernel-image setups are not examined.
- The report sees systemd as a normal user does; other users' processes are not inspected.
- It has been used on one real machine so far.

## For packagers

- **Source:** `https://github.com/pardhuvarmax/emrac/archive/refs/tags/r3.tar.gz`.
- **Build:** `cargo build --release --locked` (the lock file is committed); pass `--remap-path-prefix` as `dev/release-build.sh` does to keep the builder's paths out. The program is the single binary `target/release/emrac`; the crate producing it is named `emrac-cli`.
- **Version:** `0.3.0`. `crates/emrac-core/data/PKGBUILD.in` is the recipe `self upgrade` and `install.sh` use; a test keeps it equal to `install.sh`'s.
- **Dependencies:** as under Requirements. The package should depend on `tar` as well as the r2 list.
